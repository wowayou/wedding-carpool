## 已定的决定（2026-10-08）

- **公开计算规则**：
  - 目的：一是打消用户的顾虑，比如「为什么让我去这个站」「是不是偏向谁」；二是给以后的优化留出空间：规则写明了、有版本号、有快照测试，以后改规则时有据可查、改动看得见。
  - 范围：
    - 一个规则说明页，作为唯一的说明来源；
    - 每个方案显示分数的构成；
    - 规则版本号；
    - 防止说明和代码对不上的测试。
  - **不做**用户可调的权重，比如「更看重少绕路」。等有了具体反馈再说。
- **赞助**：
  - **只放在仓库里**，站点上不放：`.github/FUNDING.yml` 和 README 一节；
  - 渠道：爱发电 `https://afdian.com/a/eigentime`，作者赞助页 `https://eigentime.org/zh/support/`；
  - GitHub Sponsors：站长要开，但账号还没开通（2026-10-08 查过，`hasSponsorsListing: false`）。开通并通过审核后，再在 FUNDING.yml 里加 `github: wowayou`，现在加的话按钮会指向无效页面；
  - 写法：写成「支持作者的开源工作」，自愿，不对应任何功能或权益，线上站点继续免费；
  - 不写「公益」「捐款」「服务器费用」「支持本站运营」。
- **站点上的「公益性质」改为「非商业」**（about、privacy 两处），免得和赞助连在一起，被理解成募捐。
- **漏洞报告**：仓库的 GitHub Private vulnerability reporting 已在 2026-10-08 开启。

### T1. 计算内核

- `Plan` 加上成本分项：
  - `rider_min`：搭上车的乘客，到上车点的用时合计；
  - `taxi_min`：打车组的到站用时，加上站到目的地的车程，合计；
  - `cost = detour + rider_min + taxi_min`，这个口径和排序都不变。
- 默认值集中到 `carpool.DEFAULTS`，加载代码改用它，行为不变：
  - `max_detour_min` 30，`max_stops` 2，`station_cost_min` 60，`station_access_min` 45；
  - `exit_buffer_min` 15，`security_min` 40；
  - `discover_radius_km` 120，`discover_limit` 10，`travel_time` "08:00"。
- 新增 `RULES_VERSION = 1`。只有排序规则或成本口径变了才加一；改界面、改文字不加。
- 报告（`render`，本地版和在线版共用）：
  - 每个方案（去程和返程）下面加一行「排序依据」，例如：`排序依据：3 人搭车；总分钟 442 = 车主多绕 37 + 乘客到上车点 405 + 打车组 0`；
  - 各分项先四舍五入，总分钟取三个分项之和，保证显示出来的算式对得上；
  - 备选方案再加一行和推荐方案的差别：
    - 人数不同：`和推荐方案比：少 1 人搭车`；
    - 人数相同：`和推荐方案比：总分钟多 25（车主多绕 +30，乘客到上车点 −5）`，只列不为 0 的分项；
  - 「说明」里讲排序的那条改成：`方案按计算规则第 1 版排序，规则和默认值见 https://carpool.eigentime.org/guide/method`。用绝对地址，和方案页页脚现有的链接一致，本地版也能打开。

### T2. 规则说明页 `/guide/method`「方案是怎么算出来的」

源文件 `web/pages/guide-method.html`，在 `site-data.mjs` 登记：
- 可以被收录；
- 面包屑：首页 › 使用指南 › 怎么算的；
- 结构化数据：`article`、`breadcrumb`。

**内容**（写法照现有指南页：短句、先结论；每一条都要能在代码里找到依据）：

1. **一句话**：
   - 先让尽量多的人搭上顺风车，再让总用时最少；
   - 没有付费排名，不偏向哪位成员；
   - 行车时间和车次相同时，算出来的结果也相同；
   - 在线版在你的浏览器里计算，服务器只转发高德查询、保存配置。
2. **用到的数据**：
   - 高德驾车测距，是查询时的路况，缓存 20 分钟；
   - 你填的车次；
   - 没填车次时，用高德公共交通估算（只有直达，可能不准）；
   - 都没有时，按默认值估算；
   - 用 12306 站名表过滤候选站。
3. **硬性条件**（不满足的组合直接不考虑）：
   - 空座；
   - 每位车主的绕路上限，返程可以单独设；
   - 每辆车最多停几次；
   - 同行的一组不拆开；
   - 返程送到站的时刻，要赶在发车前的提前量之前；
   - 只停有人上下车的点。
4. **排序**，按顺序比：
   1. 搭车人数，按同行人数算，多的在前；
   2. 总分钟，少的在前；
   3. 停车次数，少的在前；
   4. 完全一样时，保留先算到的那个（和成员的填写顺序有关）。

   各分项的口径：
   - **车主多绕**：接人路线的全程，减去直达；
   - **乘客到上车点**：
     - 在家附近上车，记 0；
     - 去车站上车：填了车次的，记「首个发车到最后到站」，再加去车站和候车的 45 分钟；只填了分钟数的，用分钟数；都没填的，用高德公共交通估算；估算不到的，记 60 分钟；
   - **打车组**：到站用时，加上站到目的地的车程。

   还有两点要说明：
   - 车主的一分钟和乘客的一分钟同等看待；
   - 同行的一组按一份算，不乘人数。
5. **时刻怎么推**：
   - 去程：车主的出发时间，从「最晚到站的人的到站时刻 + 出站 15 分钟」往回推；
   - 返程：从散场时间往后推，要在发车前 40 分钟到站；
   - 打车费粗估：按每分钟约 1 公里、每公里 2–3 元，每 4 人一辆车。
6. **默认值表**：每个默认值所在的单元格带 `data-default="<DEFAULTS 的键>"`，测试会拿它和代码核对。
7. **算得完的代价**：车很多的时候，为了能在浏览器里算完，每辆车只保留绕路最少的若干条路线，结果不一定是理论上的最优。
8. **目前没考虑的**，这些也是以后可能改进的方向：
   - 几位车主之间负担是否均衡；
   - 等人的时间不计入总分钟：车主在站里等乘客，乘客在站里等车主；
   - 过路费、油费、停车费；
   - 出发当时的路况；
   - 高铁换乘和刚开通的线路（公共交通估算查不到）；
   - 站里停车和出站口的实际条件；
   - 同行人数多时，乘客用时要不要按人数加权。

   有想法请到 GitHub 提 issue。
9. **规则版本**：
   - 现在是第 1 版（2026-10）；
   - 方案页页脚会标明用哪一版算的；
   - 以后改排序或口径，会升版本，并在更新记录里写明原因。
10. **源码**：链接到 GitHub 上的 `carpool.py`，指明 `solve`、`evaluate`、`assign`。
