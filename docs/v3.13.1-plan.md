# v3.13.1 计划：手机上编辑页的地图缩到最小、看不清

站长 2026-10-20 反馈：「手机上试玩页面的地图没法看」。主代理复现并定位，Sonnet 执行，主代理验收。发布照常要等站长同意。

## 零、开工前的状态（2026-10-20）

- 本地 `main`、`origin/main`、线上都是 3.13.0。

## 一、现象（2026-10-20 在线上复现）

在线上 `/try` 用 Playwright 模拟手机（iPhone 13，390×664），只读，没有保存：

- 打开后点底部「地图」页签：地图缩到了最小一级，整个世界只占一小块，所有点叠在目的地那一个位置上，图例盖住半屏。
- 点「计算方案」（手机上算完自动切到「方案」），再点「地图」：方案的路线同样缩成一团。
- 桌面宽度（三块同时显示）正常。示例页 `/demo` 在手机上正常（路线铺满地图）。
- 在线编辑页 `/t/…` 和本地版用的是同一个编辑器，手机上也会这样。

## 二、根因

- 手机上（宽度 959 以下）「填写 / 地图 / 方案」三块用底部页签切换，不在当前页签的那块是隐藏的，地图容器的尺寸是 0×0。
- 行程载入时 `drawPreview()` 调 `fitBounds`，算完方案时 `drawPlan(true)` 也调 `fitBounds`。这时地图在隐藏的页签里，Leaflet 按 0×0 的尺寸算缩放级别，结果缩到最小一级。
- `drawPreview()` 随后把 `state.fitted` 设成 true。切到「地图」页签时，`layout.setPane('map')` 只调了 `invalidateSize()`，`state.fitted` 已经是 true，不会再缩放一次；方案的缩放根本没有补做的地方。
- 现有 e2e（`试玩：手机宽度的三个页签……`）只检查了哪块可见，没检查地图的视野，所以没测出来。

## 三、修法

在 `web/editor/map.js` 加一个缩放函数，三处 `fitBounds` 都改走它：

- 地图容器实际尺寸是 0 时（看 `view.map.getContainer()` 的 `clientWidth`、`clientHeight`，不要看 `getSize()`，它有缓存），不缩放，只把这次的范围和参数记成「待缩放」，后来的覆盖先前的；尺寸正常就直接缩放，并清掉「待缩放」。
- 三处：
  - `map.js` 的 `drawPreview`；
  - `map.js` 的 `drawPlan(fit)`；
  - `sug-layer.js` 的 `fitSugLayer`：它现在用 `getSize().x < 50` 判断，也改成走这个函数，或者至少判断实际尺寸。保持它「返回是否缩放过」的约定，`sug.fitted` 的逻辑不能被改坏。
- 地图变得可见、尺寸变了以后，先 `invalidateSize()`，再补做「待缩放」：
  - `layout.setPane('map')`；
  - `wire.js` 里窄屏和宽屏切换（`narrow()` 的 `change`）时。
- `state.fitted` 的含义不变（「预览已经缩放过」，换行程、恢复示例时清零）。待缩放还没补做时，不要让它重复缩放。

不要做的：不改布局和样式，不改桌面宽度的行为，不动地图库和瓦片（底图以后要换成高德 JS API，另做计划；这次只修缩放），不顺手重构别的。
