# v3.16 计划（摸底）：地图改用高德 JS API

站长 2026-10-21 同意先摸底。这是高德商务 10-15 来电后的整改之一。对方的原话是：「用 Leaflet 直接加载高德瓦片……好像这个是不支持的，高德应该还是得用官方的那个 JS API。」

这份文件现在只是**摸底计划**：先弄清楚几个技术问题，再定改哪些页面、怎么改，然后才写实现计划。

## 零、现在的地图

| 页面 | 地图 | 安全策略（CSP） |
|---|---|---|
| 编辑页（含试玩、本地版） | Leaflet，自己托管在 `/vendor/`，直接加载高德瓦片 `webrd0x.is.autonavi.com` | 不允许 `unsafe-eval`，不放行任何 CDN 的脚本；`img-src` 放行高德瓦片 |
| 示例页 `/demo` | Leaflet，从 cdnjs 加载，带 SRI | 放行 cdnjs |
| 方案页 `/p/…` | 同上；页面放在 CSP 沙箱里（匿名来源，不能发请求） | 同上 |

## 一、已经查到的（2026-10-21，主代理）

用一个无效 Key 取了 JS API 2.0 的加载脚本，没有用真实 Key：

- `https://webapi.amap.com/maps?v=2.0&key=…`：
  - 约 970 KB；
  - 内容里直接写着 Key 和配置，每个 Key 不一样。所以**没法自己托管，也没法加 SRI**，只能从高德的服务器实时加载。
- 脚本里有 `eval(` 两处、`new Function` 四处，还会把一段代码拼成字符串去建 Web Worker。所以很可能要放行：
  - `script-src` 里的 `unsafe-eval`；
  - `worker-src` 里的 `blob:`。
- 引用到的域名有 `webapi`、`restapi`、`vdata`、`mvt`、`a`、`o4`、`jsapi`、`jsapi-service`、`custyle` 等十几个 `*.amap.com`。
- `https://webapi.amap.com/loader.js`（官方加载器）约 5 KB，本身没有 `eval`。

**结论（推断，要实测确认）**：把 JS API 直接放进编辑页，要放宽编辑页的安全策略：放行 `webapi.amap.com` 的脚本、`unsafe-eval`、`blob:` Worker、十几个 `*.amap.com` 的连接和图片。这和 README「安全措施」里「不允许 unsafe-eval、不放行任何 CDN」相反。编辑页里有编辑链接的密钥和多人同步，放宽代价不小。

## 二、要摸清的

1. **能不能隔离**：
   - 地图放进一个单独的同源 iframe 页面（比如 `/map-frame`），只有这个页面放宽安全策略；
   - 编辑页、示例页、方案页用 `postMessage` 把点和线交给它画；
   - 编辑页自己的安全策略不变。
   - 要验证：地图交互（缩放、悬停标签、自适应范围）在 iframe 里好不好用；手机上的页签切换（3.13.1 修的那种缩放问题）在 iframe 里怎么处理。
2. **Key 和安全密钥**：JS API 的 Key 需要配安全密钥（`securityJsCode`）。有两种放法：
   - 明文写进页面：高德文档说只适合开发；
   - 经服务端转发（`serviceHost`）：就又经过我们的服务器了。
   - 要实测：只显示地图、不用 JS API 的路线和搜索服务时，安全密钥要不要，哪种放法可以。
3. **配额**：
   - 个人账户的 JS API「地图加载」有没有免费额度、是多少；
   - 试玩页、示例页、方案页给不登录的访客看，打开一次地图算不算一次（爬虫也会打开）。
   - 控制台里看一次实测的计数。
4. **方案页的沙箱**：方案页是用户上传的 HTML，放在 CSP 沙箱里，不能发请求。
   - 加载 JS API 就得放开网络，这和「方案页的 HTML 由编辑者的浏览器上传，所以放进沙箱」的安全设计冲突。
   - 备选：方案页不放地图，改成「在高德里看」的链接，或者用一张不调用高德的示意图（只画点和线，不画底图）。
5. **坐标和画法**：
   - 现在的点、线、标签、图例、找站的圈都是 Leaflet 画的，换 JS API 要逐个对应（`AMap.Marker`、`AMap.Polyline`、`AMap.Circle`、`AMap.Text`）；
   - 坐标本来就是高德坐标（GCJ-02），不用换算。

## 三、需要站长做的

在高德控制台建一个 JS API 的 Key：「应用管理 → 我的应用 → 添加 Key」，服务平台选「Web 端（JS API）」。

- 域名白名单填 `carpool.eigentime.org`；本机测试还要加 `localhost` 和 `127.0.0.1`，控制台允许的话就加。
- 建好后有一个 Key 和一个安全密钥。**不要发在聊天里**，写进本仓库根目录的 `.dev.vars`（已被 git 忽略）：
  ```
  AMAP_JS_KEY=...
  AMAP_JS_CODE=...
  ```
- 主代理用它在本机做一个最小的测试页，把第二节 1–4 逐项实测，结果写回这份文件，再出实现方案给站长定。

## 四、摸底的结果（2026-10-21，主代理）

**怎么测的**：
- 测试页和小服务器都在草稿目录，不进仓库。小服务器可以按页面给不同的安全策略。
- 用站长建的 JS API Key，在本机用 Playwright 的 Chromium 打开测试页。
- 测试页画的是几个点、一条线、一个圈、几个标签，再自适应范围。用 `securitypolicyviolation` 事件和控制台收集被安全策略拦下的请求。
- 截图看画出来的效果。一共打开了大约 12 次地图。

| # | 问题 | 结果 |
|---|---|---|
| 1 | 能不能画 | 能。点、线、圈、标签、自适应范围都正常。底图是 `webrd0x.is.autonavi.com` 的栅格瓦片，和现在 Leaflet 加载的是同一套，只是改由 JS API 加载 |
| 2 | 要不要安全密钥 | **只显示地图不需要**：不配 `securityJsCode` 也能正常画完。所以页面里不放安全密钥；`AMAP_JS_CODE` 留着，以后用 JS API 的路线或搜索服务时再说 |
| 3 | 最少要放开哪些安全策略 | 见下面「地图页面的安全策略」。**`unsafe-eval` 是必需的**：不放开，地图停在「已创建」，到不了「加载完成」 |
| 4 | 能不能隔离在 iframe 里 | **能**。父页面用严格策略（`script-src 'self'`，不加载任何高德脚本，只多一条 `frame-src 'self'`），地图在同源 iframe 里，用 `postMessage` 传「要画什么」，画完回报。父页面没有任何违规 |
| 5 | 方案页（CSP 沙箱）能不能用 | **能**。模仿方案页：沙箱、`connect-src 'none'`、只允许自己的脚本，再嵌同一个地图小页面。父页面来源是 `null`，所以消息按「`e.source` 是不是对方窗口」来认，不按来源认。方案页自己的安全策略不用放宽，只加 `frame-src`。地图直接放在沙箱页面里也能画，但会有几条不影响显示的报错 |
| 6 | 域名白名单 | 从 `127.0.0.1`、`localhost`、`127.0.0.2` 打开都能画。`127.0.0.2` 不太可能在白名单里，所以**要站长看一眼控制台**：这个 Key 的白名单设了什么。JS Key 会出现在公开页面里，白名单是防止别人拿去用的唯一办法 |
| 7 | 配额 | 高德计费页（`lbs.amap.com/upgrade`，2026-10-21 读）把「JS 地图图面初始化」归在「基础地图定位服务」，个人认证开发者每月免费 150 万次（超出 3 元/万次）。每打开一次地图算一次；按现在的访问量（近 30 天几十次页面访问），远远用不完。表格的列是按排版对应的，以控制台为准 |

**地图页面的安全策略**（实测能用的最小集合）：

```
default-src 'none';
script-src 'self' https://webapi.amap.com https://jsapi-service.amap.com https://restapi.amap.com https://vdata.amap.com 'wasm-unsafe-eval' 'unsafe-eval';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: https://*.amap.com https://*.is.autonavi.com;
connect-src 'self' https://*.amap.com
```

- 还剩一条违规：一个 `javascript:` 地址，在高德的标志链接一类地方，不影响画图。
- `vdata.amap.com` 是高德的点击统计（JSONP），不放行也能画，放行是为了不报错。

**JS API 会连的域名**：
- 脚本：`webapi`、`jsapi-service`（插件）、`restapi`（启动日志，JSONP）、`vdata`；
- 连接：`jsapi`；
- 图片：`webapi`、`webrd01–04.is.autonavi.com`。

## 五、建议的做法（等站长定）

1. **一个地图小页面 `/map`**：
   - 同源，只有它用上面那套宽松的安全策略；
   - 编辑页（含试玩）、示例页、方案页都用 iframe 嵌它；
   - 外面的页面用 `postMessage` 告诉它「画什么」：点、线、圈、标签和优先级、要不要自适应范围、图例；
   - 编辑页、示例页、方案页自己的安全策略不放宽，只加 `frame-src 'self'`。
   - 编辑页现在画地图的代码（`web/editor/map.js`、`sug-layer.js`）改成生成这份「要画什么」的数据；真正画图的代码挪进 `/map`，用 `AMap.Map`、`CircleMarker`、`Polyline`、`Circle`、`Text`。
   - 方案页（`share.py`）和示例页同样改成嵌 `/map`。
2. **不配安全密钥**。JS Key 写在 Worker 的普通变量里（`AMAP_JS_KEY`，不是秘密），构建或返回 `/map` 时填进去。**前提是控制台设好域名白名单**（第四节第 6 条）。
3. **手机页签**：iframe 在隐藏的页签里同样是 0 尺寸。延续 3.13.1 的做法：外面的页面切到「地图」时，发消息让 `/map` 重新计算尺寸，再补做缩放。
4. **本地版**（`python3 ui.py`）：
   - 也嵌 `/map` 那份页面（本地版自己提供）。
   - 本机配了 `AMAP_JS_KEY` 就用 JS API；没配就不画底图，只画点和线。
   - 不再用 Leaflet 加载高德瓦片。
   - 要站长定：可以接受本地版没配 JS Key 时没有底图吗？
5. **自部署**：要自己的 JS Key（`wrangler.jsonc` 的 `vars` 里设 `AMAP_JS_KEY`）；不设就不画底图。CHANGELOG 按「不兼容」写明。
6. **Leaflet 的自托管**：Leaflet 不再需要，从 `/vendor/` 去掉；marked 不受影响。

**工作量**：
- 中等偏大，主要在把三处画图代码统一成一份「要画什么」的数据，再在 `/map` 里用 JS API 画出来。
- 估计分 3 个切片：
  - `/map` 页面和消息协议；
  - 编辑页（含找站图层、手机页签）；
  - 示例页、方案页、本地版和文档。
- 发布前出预览页。

**要站长定的**：
- 第五节的做法，尤其第 4 条本地版没有 JS Key 时不画底图；
- 去高德控制台确认这个 JS Key 的域名白名单（第四节第 6 条）。

**站长的决定（2026-10-21）**：同意第五节的做法，包括本地版没配 JS Key 时不画底图。站长说之前没加域名白名单，现在加上了。

**白名单复核（2026-10-21，主代理）**：
- 带不同的 Referer 取 JS API 主脚本：
  - `https://carpool.eigentime.org/` 正常返回脚本；
  - `localhost`、`127.0.0.1`、`127.0.0.2`、`example.com` 都返回 `INVALID_USER_DOMAIN`（10006）。
- 结论：白名单生效。线上的 Key 只能在本站用；本机开发看不到真实底图（见第六节「本机开发用的 Key」）。

主代理出方案和验收，Sonnet 按切片执行。编辑页、示例页、方案页的地图外观都会变，发布前出预览页；发布照常要等站长同意。

### 补充实测：方案页的嵌入限制（2026-10-21）

- 地图小页面如果加 `frame-ancestors 'self'`（只许本站页面嵌入），模仿方案页的沙箱页面就嵌不进去了。
- 沙箱页面的来源是匿名的（`null`），换成写站点地址也一样不匹配。
- 所以分两个入口：
  - **`/map`**：编辑页、试玩、示例页用，加 `frame-ancestors 'self'`，别的网站嵌不了。
  - **`/map/share`**：方案页用，没法加 `frame-ancestors`。改由 Worker 看请求的 Referer：只有从本站 `/p/…` 打开的才返回地图页面，别的来源（包括没有 Referer 的）返回 403。这样别的网站嵌它，就借不到我们的 Key。实现时用本地 wrangler 实测：方案页发出的 Referer 是不是 `/p/…`。

### 设计

1. **画什么（scene）**：
   - 一份纯数据，由外面的页面生成，用 `postMessage` 交给地图页面。内容有：
     - 点：坐标、种类（目的地、车站、开车的、不开车的）、名字、附注、优先级、是否高亮；
     - 线：坐标串、颜色、粗细、虚线、悬停文字；
     - 圈：圆心、半径、样式，找站用；
     - 要不要自适应范围，以及留白（抽屉遮住的那一截）；
     - 图例的几行；
     - 深色还是浅色。
   - 消息格式写成一个模块（如 `web/map/scene.js`），外面和里面共用；测试核对字段。
   - 地图页面回报：`ready`（可以接收）、`drawn`（画完）、`fail`（JS API 没加载出来）。
2. **地图页面**（`web/map.html` 加脚本，构建到 `dist/`）：
   - Key 由服务端填进页面的 `<meta name="amap-js-key">`：线上由 Worker 改写返回的页面，本地版由 `ui.py` 填。
   - 有 Key：加载 JS API 2.0，用 `AMap.Map`、`CircleMarker`、`Polyline`、`Circle`、`Text` 画。深色用高德自带的深色样式（`amap://styles/dark`），不用 CSS 滤镜。
   - 没有 Key，或者 JS API 加载失败：用一个不带底图的简单画法（墨卡托投影，SVG 或 canvas）画点、线、圈和标签，角上写「没有底图」。
   - 标签互相遮挡时，按优先级只留前面的，沿用现在 `declutter` 的规则；悬停再显示。
   - 尺寸变了（手机页签切换）：外面的页面发 `resize`，地图页面重新计算尺寸，再补做最近一次自适应范围。延续 3.13.1。
   - 安全策略用第四节实测的那套；`/map` 另加 `frame-ancestors 'self'`。
   - 不配安全密钥（`securityJsCode`）。
3. **编辑页（含试玩、本地版）**：
   - `web/editor/map.js`、`sug-layer.js` 改成生成 scene、管 iframe 和消息，不再引用 Leaflet；
   - 编辑页的安全策略去掉高德瓦片和 Leaflet，只加 `frame-src 'self'`；
   - `web/vendor.mjs` 不再下载 Leaflet，`/vendor/leaflet` 去掉，许可证随之去掉；
   - 地图组件加载失败时的「重试」提示，换成地图页面回报 `fail` 时显示。
4. **方案页**（`share.py`）：
   - 留着现在的 `data` JSON，删掉 Leaflet 脚本；
   - 换成 iframe 嵌 `/map/share`，内联脚本把 `data` 转成 scene 发过去，用 `'*'` 发；地图页面只认 `e.source === parent`；
   - 打印：iframe 固定高度；
   - Worker 的 `SHARE_CSP` 去掉 cdnjs 和高德瓦片，加 `frame-src` 本站。
   - **旧方案页**：HTML 里写死了 Leaflet。新的安全策略会拦掉 Leaflet，而旧页面的脚本本来就是「Leaflet 没加载就把地图那块藏起来」，所以旧页面不显示地图，其余照常。重新发布就有新地图。CHANGELOG 写明。
5. **示例页** `/demo`（`web/demo.html`，由 `web/make_demo.py` 生成）：和方案页同样改，但嵌的是 `/map`，示例页是同源、不在沙箱里。示例内容不重新生成（要调用高德），只换地图那一段。
6. **本地版**：
   - `ui.py` 提供 `/map` 和 `/map/share`；
   - Key 读环境变量 `AMAP_JS_KEY` 或同目录的 `.amap_js_key`（加进 `.gitignore`）；
   - 没有就走不带底图的画法。
7. **Worker 和配置**：
   - `/map`、`/map/share` 走 `run_worker_first`，Worker 填 Key、加安全策略，`/map/share` 检查 Referer；
   - Key 是 `env.AMAP_JS_KEY`，线上用 `wrangler secret put AMAP_JS_KEY` 设：它不是秘密，但别写进仓库，免得自部署的人误用；
   - 不设就是不带底图的画法。
8. **隐私页、README**：
   - 地图改由高德 JS API 加载，打开地图时浏览器会连高德的多个域名；
   - 安全措施一节写明「地图隔离在单独的页面里，只有它放开 `unsafe-eval`」；
   - 自部署要设 `AMAP_JS_KEY`（不设没有底图），并在高德控制台设域名白名单；
   - CHANGELOG 标「不兼容」：自部署要多设一个变量。

**假 JS API**（e2e 用）：
- 拦下 `webapi.amap.com/maps` 的请求，返回一个很小的 `AMap` 替身；

### 本机开发用的 Key（可选，建议做）

- 线上的 Key 只认 `carpool.eigentime.org`，本机打开会被高德拒绝，本机只能看到不带底图的画法。

**scene 格式**（坐标都是 `[lng, lat]`，详见 `scene.js` 顶部注释）：
- `v: 1`、`theme: light|dark`；
- `points[]`：`lng lat kind(venue|st|car|home) name notes? priority? highlight? radius?`；

**Referer 实测结论（重要，需要主代理定）**：
- 方案页（Chromium，CSP 沙箱，来源 null）发出的 iframe 请求**没有 Referer**，不管 iframe 的 `referrerpolicy` 写什么（`unsafe-url` 也一样）。用一个 node 小服务器和 wrangler 各测了一次，结果一致。非沙箱的页面发的 Referer 正常。
- 所以真的方案页嵌 `/map/share`，按「没有 Referer 就 403」的规则会被拒：地图空白。`map.test.mjs` 里「已知问题」一条断言了这个现状。
- 另外：非沙箱的 `/p/…` 页面，Referer 要完整路径，iframe 要写 `referrerpolicy="no-referrer-when-downgrade"`（方案页自己的 `strict-origin` 只带来源）；写 `same-origin` 不行（沙箱页面对本站也算跨源）。
- 可选的办法（没有改，等定）：A）没有 Referer 时，只要 `Sec-Fetch-Dest: iframe` 且 `Sec-Fetch-Site: cross-site` 也放行（挡得住直接打开和别的网站直接嵌，挡不住别人用沙箱页面再套一层）；B）方案页返回时由 Worker 往 iframe 地址里放一个签名的短期令牌，`/map/share` 校验令牌；C）取消检查，只靠高德控制台的域名白名单。
- e2e 里沙箱页面的消息机制（来源 null、脚本加载、按 `e.source` 认父窗口）是让测试进程带着 `/p/…` 的 Referer 去问 wrangler 再把响应交给浏览器来模拟的（Playwright 改不了真实请求的 Referer）。

### 切片 1 主代理验收和 `/map/share` 的决定（2026-10-21）

- **自己重跑**：`npm test` Node 176 项、Python 259 项全过；`npm run e2e` 38 项全过。
- **Referer 的发现**：真实 Chromium 里，CSP 沙箱页面（来源 `null`）发出的 iframe 请求不带 Referer，`referrerpolicy` 怎么写都一样。所以「只认 `/p/…` 的 Referer」会把真的方案页挡掉。
- **决定，采用切片 1 汇报里的方案 A**：
  - 规则：
    - Referer 是本站 `/p/…`：放行；
    - 没有 Referer，但 `Sec-Fetch-Dest: iframe` 且 `Sec-Fetch-Site: cross-site`（沙箱页面嵌入时就是这样）：放行；
    - 其他情况（直接打开、别的网站带着自己的 Referer 嵌入、不支持 Fetch Metadata 的旧浏览器）：403。
  - **剩下的风险**：
    - 别的网站嵌入时把 Referer 关掉（`referrerpolicy="no-referrer"`），就能嵌进去，用我们的 Key 画它自己的地图；
    - 后果只是消耗「JS 地图图面初始化」额度（个人每月 150 万次，用完就停，不会扣费），拿不到任何数据；
    - 签名令牌（方案 B）也只能多挡一层，别人照样可以从公开的方案页取到新令牌。
    - 所以先用 A，在隐私页或 README 的安全一节如实写；以后如果发现被滥用，再加签名令牌，或者按 IP 限流。
- **还没验证**：高德画法没有对着真实 JS API 看过。线上的 Key 只认本站域名，本机打不开。要么站长建本机开发用的 Key，要么发布前在线上用一个测试页面看。不能只凭假 JS API 就发布。
