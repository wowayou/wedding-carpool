# v3.15 计划：自己的高德 Key 只留在浏览器里

站长 2026-10-21 同意（「go」）。这是高德商务 10-15 来电后的整改之一。对方的原话是：把 Key 给别人用，「别人的主体、他的应用是什么，跟您和高德的合约里是没有包含的，可能会带来一些不必要的风险，以及盗用 Key 的情况」；站长提出 Key 只存在本地、不发到服务器，对方说「那可能会好一点」。

主代理出方案和验收，Sonnet 执行。首页和编辑页的文字、对话框会变，发布前出私密预览页；发布照常要等站长同意。

## 零、开工前的状态（2026-10-21）

- 本地 `main`、`origin/main`、线上都是 3.14.0。
- `npm test`：Node 145 项、Python 249 项全过；`npm run e2e` 22 项全过（3.14.0 发布时实测）。

## 一、现在怎么做的

| 环节 | 现在 | 位置 |
|---|---|---|
| 新建「用自己的 Key」的行程 | 首页把 Key 发给服务端；服务端用它调一次高德验证（`amapKeyProblem`），通过后存进行程实例的 meta | `web/landing.html`、`web/worker.js` 的 `createTrip`、`ConfigRoom.init` |
| 公共额度用完，改用自己的 Key | 编辑页把 Key 发到 `/api/t/<id>/key`，服务端验证后存进 meta | `web/editor/backend.js` 的 `setOwnKey`、`worker.js` 的 `/key`、`ConfigRoom` 的 `/set-key` |
| 计算、搜索 | 浏览器里的 Pyodide 把请求发给 Worker 的 `/amap-batch`；Worker 从 meta 取出 Key，代为调用高德，带节点缓存、每秒 3 次限速、每个行程每天 3000 次的上限、按 Key 记的配额标记 | `browser.BrowserAmap`、`worker.js` 的 `tripAmap` |

所以用户的 Key 现在会经过服务端、存在服务端，调用也从服务端（香港节点）发出。

## 二、改成什么样

**原则**：用户自己的 Key 不发给服务端，服务端不保存、不经手；用这个 Key 的调用，由用户的浏览器直接发给高德。

- 2026-10-20 已核对：`restapi.amap.com` 的 v3、v5 接口都返回 `Access-Control-Allow-Origin: *`，网页可以直接调用。
- 顺带的好处：这类调用从用户自己的网络发出，不再从香港节点发出；也不经过节点缓存，和高德「不让存」的口径一致。

### 1. Key 存在哪

- 存在这台设备浏览器的 `localStorage`，一台设备一个，所有「用自己的 Key」的行程共用。读写都包在 try/catch 里；读不到时当作没填。
- 编辑页「更多」里显示「这台设备上的高德 Key：已填（尾号 xxxx）」，可以更换、清除。
- 不进行程配置、历史版本、导出的 JSON、方案页。

### 2. 新建行程

- 首页选「用自己的高德 Key」：
  - 浏览器先校验格式（32 位字母和数字）；
  - 再直接请求高德做一次验证（地理编码「北京市」）。和现在服务端的判断一样：配额用完、频率超限不算 Key 无效。
  - 通过后存进本机，再请求服务端新建行程。请求里**不带 Key**，只说明是「自己的 Key」模式。
- 服务端照旧过新建限速（每个来源每天、全站每天），不再验 Key。

### 3. 公共额度用完，改用自己的 Key

- 编辑页的对话框同样在浏览器里验证、存本机。
- 然后告诉服务端「这个行程改用自己的 Key」，请求里不带 Key。
- 服务端把行程改成自己的 Key 模式，邀请码名额照旧还回去（现有逻辑）。

### 4. 计算和搜索

- Pyodide 初始化时，自己的 Key 模式传入 Key，用新的 `browser.DirectAmap`：
  - 继承 `carpool.Amap`，沿用它的间隔、重试和配额判断；
  - 只把「怎么发请求」换成同步 XHR 直接 GET `https://restapi.amap.com`。
  - 它也是 `AmapLike` 的一个实现，测试要核对它满足接口。
- **安全上限**：每台设备、每个行程、每个北京日最多 3000 次（沿用现在 `OWN_TRIP_DAILY_LIMIT` 的默认值）。计数存在 `localStorage`，只防程序出错时无限调用；到上限停下提示。
- **这台设备没填 Key**：一起编辑的人用编辑链接打开，没有 Key 也能编辑；点「计算方案」或搜索时，提示「这个行程用自己的高德 Key，这台设备上还没填」，并给出填 Key 的入口。
- **预取**：现在 `BrowserAmap.prefetch` 是把一批请求交给 Worker 并发去取。直连时先逐个发、按间隔走，和本地版一样。
  - 记下改前改后「试玩规模」的计算要多少次请求、大约多久，写进完成情况。
  - 太慢的话，另开一项改并发，这一版不做。

### 5. 服务端

- `createTrip`：自己的 Key 模式不再接收、验证、保存 Key；请求里带了 `amapKey` 也不读。
- `/key` 改成「改用自己的 Key」：不带 Key，只改模式。接口名可以保留，也可以换成更直白的名字，和前端一起改。
- `ConfigRoom`：
  - meta 不再有 `amapKey`；
  - `/amap-take` 遇到自己的 Key 模式时，返回明确的错误，例如 `OWN_KEY_IN_BROWSER`：「这个行程用自己的 Key，由浏览器直接调用；请刷新页面」，防止旧页面还在走代理；
  - `/set-key` 改成只改模式。
- **已经存下的 Key**：
  - 行程实例下次收到任何请求时，发现 meta 里还有 `amapKey`，就删掉并写回，即懒删除；
  - 行程到期删除时本来就一起删；
  - 隐私页和 CHANGELOG 写明这一点。
- **删掉不再用的**：
  - `amapKeyProblem`；
  - 代理里「自己的 Key 模式用 meta 里的 Key」那条分支；
  - `OWN_TRIP_DAILY_LIMIT`（README 里的说明一起删；已经设了这个变量也不影响）。
- 公共额度（邀请码、站长 Key）的代理、缓存、护栏**完全不动**。

### 6. 安全策略（CSP）

- 编辑页和计算线程（Pyodide 的 Web Worker）的 `connect-src` 加上 `https://restapi.amap.com`，别的页面不加。
- `web/build.mjs` 里两处都要改（页面的和 Worker 的）。
- 测试核对：编辑页和计算线程放行了，首页、方案页、管理页没放行。
- 首页的 Key 验证也是浏览器直连，首页同样要放行。所以「首页没放行」改成「首页只放行这一个地址」。

### 7. 文字

- 首页、编辑页的说明：Key 只存在这台设备的浏览器里，本站服务器不保存、不经手；计算时浏览器直接请求高德，所以高德能看到你的 IP；换设备要再填一次。
- 隐私页（`web/privacy.html`）：
  - 「自带的高德 Key」一行改写；
  - 「高德配额标记」只剩站点公共额度；
  - 「给了哪些第三方」写明自己的 Key 模式下浏览器直接连高德；
  - 3.15 以前存下的 Key 怎么删：下次打开行程时删，或者随行程到期删除。
- 关于页、使用指南、`web/site-data.mjs`（常见问题）、README（在线版、管理页、自部署、可选变量）里凡是写「Key 只保存在服务端」「代你调用」的，都同步。用 grep 找全：「服务端」「代你调用」「自带 Key」「自己的 Key」「OWN_TRIP_DAILY_LIMIT」。

## 五、验收

- **服务端**（`web/worker.test.mjs`）：
  - 新建时带了 `amapKey` 也不保存（读 meta 确认），也不对外请求；
  - 改用自己的 Key 不带 Key，只改模式，邀请码名额还回去；
  - 自己的 Key 模式的行程请求 `/amap-batch` 返回 `OWN_KEY_IN_BROWSER`，并且不对外请求；
  - meta 里有旧 `amapKey` 的行程，收到一次请求后就没有了；
  - 公共额度行程的代理行为不变（现有用例全过）。
- **浏览器**：
  - `DirectAmap` 拼出的网址指向 `restapi.amap.com` 并带上 Key，满足 `AmapLike`；
  - 每天上限到了就停；
  - 没填 Key 时计算给出提示；
  - CSP 只在该放行的页面放行 `restapi.amap.com`。
- **e2e**：第四节切片 3 的两条；原有 22 项全过。
- `npm test`、`npm run e2e` 全过。
- 截图（给预览页，放草稿目录，不进仓库）：
  - 首页「用自己的高德 Key」那一块：桌面浅色、手机深色；
  - 编辑页「更多」里的 Key 状态；
  - 没填 Key 时点计算的提示；
  - 公共额度用完时改用自己的 Key 的对话框；

## 六、完成情况

### 切片 1、2（2026-10-21，Sonnet 执行）

**切片 1：服务端（`web/worker.js`、`web/worker.test.mjs`）**

- 新建：`POST /api/trips` 的自己的 Key 模式改成 `{ own: true }`；只带 `amapKey` 不带 `own` 返回 400。带了 `amapKey` 也不读、不验、不存，不对外请求，仍先过新建限速。
- 改用自己的 Key：`POST /api/t/<id>/key` 换成 `POST /api/t/<id>/own-mode`（旧路径 404），不收 Key，只把模式改成 `own`、清行程当天用量、还回邀请码名额、广播 `meta`。行程实例内部接口 `/set-key` 改名 `/set-own-mode`。
- 代理：自己的 Key 模式的行程，`/amap-batch`、`/amap/*` 在 `/amap-take` 就返回 409，`info: OWN_KEY_IN_BROWSER`，`error:「这个行程用自己的 Key，由浏览器直接调用；请刷新页面」`，不对外请求、不占用量。
- 懒删除：`ConfigRoom.handle` 读到 meta 后，若还有 `amapKey` 就删掉写回（任何请求都触发，包括密钥不对的）。`init` 不再有 `amapKey` 参数，meta 里不再出现这个字段。
- 删掉：`amapKeyProblem`、代理里自己 Key 的分支、`DEFAULT_OWN_TRIP_DAILY_LIMIT` 和 `OWN_TRIP_DAILY_LIMIT`、`take` 里的 `ownLimit`。公共额度的代理、缓存、护栏没动。
- 用例：改写了依赖旧流程的用例（新建、代理、每日上限、配额按 Key 停、内部接口、init 校验、S-5/D-4、S-7/D-8、改用自己的 Key、邀请码名额、应急开关两条、统计），新增 3 个（带 `amapKey` 也不存、自己的 Key 模式代理一律拒绝、懒删除）。在没改实现的代码上跑，这些用例中 13 个失败（含新增的 3 个），原因是旧代码要求 `amapKey`（`{ own: true }` 返回「要么填邀请码，要么填自己的高德 Key」400）、旧代码会用 meta 里的 Key 代理、`/own-mode` 不存在。
- 改了的断言：原来「自带 Key 的行程能代理成功、用 `OWN_KEY` 调高德」的断言，改成「返回 `OWN_KEY_IN_BROWSER` 且没有对外请求」；「验证 Key 无效返回 400」「新建先过限速再验 Key」两处去掉验 Key 的部分（服务端不再验），保留限速断言。

**切片 2：浏览器**

- `browser.DirectAmap(key)`（`browser.py`）：继承 `carpool.Amap`，沿用间隔、重试、配额判断，`_fetch` 换成同步 XHR GET `https://restapi.amap.com…`。XHR 失败时只抛「网络连不上高德」，不带网址（网址里有 Key）。没有批量预取（继承 `Amap` 的空实现），逐个请求。`AmapLike`、`AmapPrefetch` 的核对测试把它加进了实现清单。
- **每日上限的做法**（每台设备、每个行程、每个北京日 3000 次，`OWN_DAILY_LIMIT`）：Web Worker 读不到 `localStorage`，所以计数在页面这边存，线程只做判断和上报。
  - 页面每次调用（计算、搜索、找站）在参数里带 `own_used: { day, count }`（今天这个行程在这台设备上已用多少），线程用它同步自己的计数（只增不减，不是今天的不算）；
  - 线程每发一次高德请求就 `postMessage({ ownUsed: { day, count } })` 报回新总数，页面写回 `localStorage`（`carpool_own_usage`，按行程编号分开，只留当天的，只增不减）；
  - 到上限抛 `QuotaError`，提示「这个行程今天在这台设备上已经用你的 Key 请求了 3000 次高德，为防程序出错先停下，没有继续调用；明天再试」。文字里特意不含「额度/配额/上限」，不会触发编辑页「公共额度用完，改用自己的 Key」的遮罩；
  - 过了北京时间零点线程自己归零。多个标签页同时算时各自带最新的已用次数，计数可能略少，但只是防程序出错，够用。
- Key 存取（`web/editor/own-key.js`，新文件）：`localStorage` 的 `carpool_amap_key`，读写都包 try/catch，读到的不是 32 位十六进制当作没填；`verifyKey` 在浏览器里直连高德验证「北京市」，配额用完、频率超限不算无效（`QUOTA_RE`、`QPS_RE` 与 `worker.js`、`landing.html` 三处一致，`ui.test.mjs` 核对）。
- 计算线程初始化（`backend.js`）：`createPy` 的初始化参数改成每次调用都重新算一遍，变了就重发 `init`（改用自己的 Key、换 Key 后不用刷新页面）；自己的 Key 模式把 `own_key` 传给线程，本机没有 Key 时直接抛 `needKey` 错误，不去连计算环境。`setOwnKey()` 不再带参数，只 POST `/own-mode`。
- 首页（`web/landing.html`）：选「用自己的高德 Key」，浏览器先验证、通过存本机，再 POST `{ name, own: true }`，请求体不带 Key。说明文字只改了一句，留给切片 4。
- 编辑页：
  - 「更多」里自己的 Key 模式多一行「这台设备上的高德 Key」：已填显示尾号 4 位，可更换、清除（清除要确认）；没填显示「填写」；「高德额度」一行改成本机的今日用量。
  - 没填 Key 时点「计算方案」或搜索，弹 Key 遮罩「这台设备上还没填高德 Key」。推荐车站的自动估算没填 Key 时只在估算栏写明，不弹遮罩。
  - 公共额度用完/主动改用自己的 Key 的遮罩，改成浏览器验证、存本机，再通知服务端改模式。四处出错处理统一走 `overlay.js` 的 `showKeyOverlay(e)`。
  - 没有新增能力项（只在 `backend.js` 里判断 `trip.mode`，其他模块按 `e.needKey` 处理），`capsFor` 没动。
- CSP（`web/build.mjs`）：首页、编辑页、试玩页的 `connect-src` 是 `'self' https://restapi.amap.com`，其余页面（示例页、管理页、隐私页、指南等）仍是 `'self'`，方案页（Worker 生成）仍是 `'none'`；`site.test.mjs` 新增断言逐页核对。计算线程是同源模块 Worker，没有单独的 CSP 响应头，构建里没有它的单独一份，编辑页这份就是 Worker 相关的全部；没在真浏览器里验证 Worker 的 `connect-src` 是否受页面策略约束，留给切片 3 的 e2e。
- 用例：Python 新增 `DirectAmapTest` 10 个（网址、直连 GET、沿用 `Amap` 规则、网络错误重试不带 Key、XHR 失败不带网址、每日上限、归零、同步用量、`handle` 初始化），`AmapLike` 核对加入 `DirectAmap`；Node `ui.test.mjs` 新增 10 个，`site.test.mjs` 新增 1 个。改前在没改实现的代码上跑，Python 的 `DirectAmapTest` 10 个全部 `AttributeError: module 'browser' has no attribute 'DirectAmap'`；Node 新用例全部失败（`./editor/own-key.js` 不存在、`/key` 路径还在、首页还把 `amapKey` 放进请求体、CSP 里没有 `restapi.amap.com`）。

**直连时「试玩规模」计算的请求数和耗时估计**（用 `DirectAmap` 配一个伪造的 `_xhr_get` 数 `/v3/*` 请求，计算本身不到 0.1 秒）：

| 场景 | 请求数 | 直连估计 | 以前（Worker 代理，每秒 3 个） |
|---|---|---|---|
| 试玩示例行程（4 人 4 站，含返程）算方案 | 19（测距 9、驾车路线 10） | 每个请求间隔 0.35 秒，加上网络往返 0.15 到 0.3 秒，约 10 到 14 秒 | 约 7 秒 |
| 4 车 6 乘客 10 站（含公共交通估算） | 101（测距 17、regeo 16、公交 60、驾车路线 8） | 约 50 到 65 秒 | 约 35 秒 |

直连比代理慢约 1.5 倍，没有做并发预取（见第三节）。

**拿不准、和计划不同的地方**

- 新建、改用自己的 Key 的接口：新建用 `own: true`，改模式用 `/own-mode`（计划里两种都允许）。
- 懒删除放在 `handle` 读到 meta 之后、密钥校验之前，所以连用错密钥的请求也会触发。
- 首页验证通过后立刻存本机，之后新建失败（限速、暂停新建）时，Key 也留在本机。
