# v3.2 计划：设计系统、整站 UI/UX、导航与 SEO/GEO、逻辑加固

定位不变：先定个大方向、心里有个底，细节同行的人再商量。分工：主代理出方案和验收，Sonnet 子代理执行。

## 已定的决定（2026-10-07）

- **设计系统放在仓库里**：
  - `web/design.css` 放设计变量和组件；
  - `/design` 是在线样式指南；
  - `docs/design-system.md` 写规范；
  - 三者以代码为准。
- **保留现在的品牌**：暖色纸底、赭红强调色，图标不变。在此基础上统一颜色、加深色模式、补齐组件。
- **不迁移到 VPS**：
  - 继续用 Cloudflare 免费套餐，零成本、免运维，余量很大。
  - 国内访问的主要风险是第三方 CDN，所以把计算环境和地图组件改为自己托管（见 D.2）。
- **流量统计在服务端做，只记按天汇总的次数**：
  - 不在网页里放统计脚本；
  - 不记 IP，不用 Cookie，追踪不到个人。
- **版本发布**：
  - 用 `CHANGELOG.md` 加 Git 标签加 GitHub Releases；
  - 自部署的人按 Releases 升级，从 v3.2.0 开始。

- 深色写法按标准三段：
  - `:root` 放浅色；
  - `@media (prefers-color-scheme: dark) { :root:not([data-theme=light]) {…} }`；
  - `:root[data-theme=dark] {…}`。
  - 深色时设 `color-scheme: dark`。
  - 页面不提供主题切换按钮，跟随系统。
- 对比度：正文和次要文字在 `--bg`、`--surface` 上要达到 WCAG AA 标准（4.5:1），说明文字至少 3:1。实现时用脚本算一遍，不达标就微调数值，并在规范里记下来。
- **字体**：
  - 系统字体栈，不加载网络字体，因为中文网络字体动辄几 MB：`-apple-system, "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`；
  - 等宽：`ui-monospace, "SF Mono", Menlo, Consolas, monospace`；
  - 时刻、次数、金额用 `font-variant-numeric: tabular-nums`。
- **字号**：12 / 13 / 14 / 16 / 18 / 22 / 28 / 36（px），正文 15px 或 16px，行高 1.65，标题行高 1.3，标题加 `text-wrap: balance`。
- **间距**：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。**圆角**：控件 8，卡片 12，标签 999。**阴影**：只用于浮层（抽屉、弹窗、下拉），卡片用边框。
- **断点**：640、960。**动效**：150ms ease-out，`prefers-reduced-motion` 时关掉。
- **焦点**：所有可交互元素有清楚的焦点框（2px 品牌色，偏移 2px），键盘可达。
- **组件**（类名统一用 `c-` 前缀，避免和页面里现有类名冲突）：
  - 按钮：主要、次要、幽灵、危险、文字链接，大中小三档，加载中、禁用两种状态；
  - 表单：输入框、下拉、多行文本、复选、单选、开关，以及「字段」（标签、提示、错误）；
  - 容器和标签：卡片、标签（状态色）、提示条（信息、成功、提醒、危险）；
  - 浮层：弹窗（替代原生 alert/confirm/prompt）、抽屉、轻提示（toast）；
  - 数据展示：表格（窄屏横向滚动）、分页签、步骤条、进度条、空状态、骨架屏；
  - 页面结构：站点页头（含手机菜单）、页脚、面包屑、代码和按键。
- **图标**：内联 SVG 图标集，24 网格，1.75 描边，`currentColor`。至少要有：车、高铁、打车、定位点、车站、复制、外链、打印、菜单、关闭、对勾、警告、信息、加号、删除、地图、编辑。不用 emoji 当图标。
- **文案规范**写进 `docs/design-system.md`：
  - 站在用户一侧，口语、简短；按钮用动词开头，比如「新建行程」「发布方案页」；
  - 报错说清楚出了什么问题、怎么办；
  - 引号用「」；说「不开车」不说「无车」；
  - 数字带单位，时间 24 小时制。
- **方案页**（`share.py` 生成，在沙箱里展示，自包含）要内嵌和 `design.css` 相同的变量，并支持深色。打印时强制浅色。加单元测试，比对两边的变量值一致。

## B. 信息架构、导航与 SEO/GEO

**页面清单**（除编辑页和管理页外都可以被收录）

| 路径 | 内容 |
|---|---|
| `/` | 首页：首屏、新建行程、效果图、适合的场合、常见问题 |
| `/demo` | 示例方案页（虚构） |
| `/guide` | 使用指南：从新建到发布的完整步骤，配截图；HowTo 结构化数据 |
| `/guide/station` | 怎么选接人的高铁站：讲清楚「最近的站不一定最好」，配示例数据 |
| `/for/wedding`、`/for/reunion`、`/for/team` | 场景页：婚礼、同学或家庭聚会、团建和公司活动。每页写这个场景的真实难点、怎么用、一个小示例、常见问题。内容要有用，不堆关键词 |
| `/about` | 关于：是什么、为什么做、谁做的、开源和授权、技术原理简述、怎么反馈 |
| `/changelog` | 更新记录，由 `CHANGELOG.md` 在构建时生成 |
| `/privacy` | 费用与隐私（已有） |
| `/design` | 样式指南（`noindex`） |
| `/admin`、`/t/…`、`/p/…` | 不收录 |
| 404 | 站内 404 页：说明可能的原因，给出首页、指南、示例的入口 |

- **页头**：
  - 左侧是标志加名称，链接到首页；
  - 中间放「示例、使用指南、场景（下拉或折叠）、常见问题、费用与隐私」；
  - 右侧放 GitHub 链接和主按钮「新建行程」，指向 `/#create`；
  - 手机上收进菜单按钮。
- **页脚**：产品（示例、指南、场景、更新记录）、关于（关于、费用与隐私、GitHub、许可证）、作者链接、LINUX DO 致谢、版本号。
- **页头页脚只写一份**：放在 `web/partials/`，构建时替换 `<!-- include:header -->` 这类占位，不在各页重复复制。版本号取 `package.json` 的 `version`。
- **编辑页和管理页**用精简页头：标志（回首页）、页面标题、各自的操作。
- **子页面**有面包屑，配 `BreadcrumbList` 结构化数据。
- **SEO 和 GEO**：
  - 每页都要有：
    - 独立的 title、description、canonical；
    - Open Graph 和 Twitter 卡片；
    - 合适的 JSON-LD（首页 `WebApplication` 加 `FAQPage`，指南 `HowTo`，场景页 `Article` 加 `FAQPage`，关于页 `AboutPage`，作者 `Person`）。
  - 结构化数据和页面上可见的文字一致，构建时校验 JSON 合法。
  - 页面之间互相链接：首页→场景页、指南；场景页→指南、示例、新建。
  - `sitemap.xml` 包含所有可收录的页面，lastmod 取构建日期；`robots.txt` 保持现状。
  - `llms.txt` 更新为导航式摘要；新增 `llms-full.txt`，放指南、选站说明、常见问题的全文纯文本，方便 AI 引用。
  - 语义化 HTML：`header`、`nav`、`main`、`article`、`footer`，标题层级正确。

## C. 编辑页 UI/UX（第二期）

- 套用设计系统，支持深色。地图瓦片在深色下略微降低亮度。
- **手机布局**：底部分页签「填写 / 地图 / 方案」，代替现在很长的单页；桌面保持左边填写、右边地图和方案。
- **原生对话框**：所有 `alert` / `confirm` / `prompt`（现在有 15 处）换成设计系统的弹窗和轻提示。删除行程时的确认改为在弹窗里输入行程名称。
- **车次表格**：手机上每个车站一行竖排，不再挤成一排。
- **状态**：
  - 计算环境加载中、失败可重试；
  - 计算中显示进度，已有；
  - 空状态：还没有方案时，说明下一步做什么。
- **方案结果**：
  - 每个方案一张卡片，关键数字放在前面：搭车人数、车主多绕、打车人数；
  - 去程、返程分开；
  - 「方案已过期」的提示更醒目，并带「重新计算」按钮。
- 方案页模板（`share.py`）套用新的变量和组件样式，打印效果不能变差。
- 管理页加流量统计面板（见 D.1）。

## D. 逻辑加固、统计、自托管依赖、版本发布（第一期，和 A、B 并行）

**D.1 服务端汇总统计**
- 按北京时间每天计数，存在 Usage DO，保留 35 天：
  1. 页面访问：首页、`/demo`、`/guide`、场景页、`/privacy`、`/about`。只算 GET 请求，并且 Accept 要含 html。
  2. 爬虫：按 UA 归类计数，分 Googlebot、bingbot、Baiduspider、Bytespider、GPTBot、ClaudeBot、PerplexityBot、其他爬虫。爬虫不计入页面访问。
  3. 来源：只记首页访问的外站 Referer **域名**（不记完整地址），以及 `?from=` 参数（只接受 `[a-z0-9-]{1,24}`）。每天每类最多记 50 个不同值，超出的计入「其他」。
  4. 转化：
     - 新建行程：按邀请码、自带 Key、管理页分开计；
     - 当天有计算的行程数：按「当天第一次领取高德额度」计；
     - 发布方案页次数；
     - 方案页被打开次数。
- 页面访问要能计数，所以这些页面的路径要加进 `run_worker_first`，由 Worker 先处理，再转给静态文件。安全头已经由 Worker 统一添加。
- 计数用 `ctx.waitUntil` 异步写，**不能拖慢页面**。
- 管理页接口 `/api/admin/stats` 返回近 30 天的统计。面板放到第二期。
- 隐私页要写明统计口径，第二期改。

**D.2 自托管前端依赖**
- 构建时下载固定版本，并校验 sha256，缓存在 gitignore 的 `.cache/`：
  - Pyodide 核心文件：`pyodide.mjs`、`pyodide.asm.js`、`pyodide.asm.wasm`、`python_stdlib.zip`、`pyodide-lock.json`，版本和现在一致；
  - Leaflet 1.9.4（js、css、images）；
  - marked 12.0.2。
- 放到 `dist/vendor/`。
- 构建时把 `dist/edit.html` 和 `dist/pyworker.js` 里的 CDN 地址改成 `/vendor/…`，并相应收紧编辑页的 CSP，去掉 jsDelivr 和 cdnjs。
- 源文件保持 CDN 地址，本地版 `ui.py` 不受影响。
- 方案页（`share.py`）仍用 cdnjs 加 SRI，保持自包含。
- 单个文件不超过 Cloudflare 静态资源 25 MiB 的上限。
- 下载代码单独放在 `web/vendor.mjs`，`build.mjs` 只调用一行，减少和其他改动的冲突。
- `LICENSING.md` 更新：说明构建产物里分发了 Pyodide（MPL-2.0）、Leaflet（BSD-2）、marked（MIT），附上它们的许可证文件。

**D.3 Worker 里的逻辑加固**
- 方案页不存在、已停止分享或已删除时，返回 HTML 页面（使用 `/design.css`），说明可能的原因，给出首页入口，状态码 404。
- 编辑链接对应的行程不存在时（已到期删除或已删除），接口返回明确的 `info: 'TRIP_GONE'`，和「密钥不对」区分开。编辑页据此提示「这个行程已经删除或到期」，第二期处理显示。
- `wrangler.jsonc` 设 `not_found_handling: "404-page"`，404 页由 A/B 那边产出 `web/404.html`。
- `/api/env` 返回版本号。

**D.4 版本发布**
- `CHANGELOG.md`：中文，按 v1 到 v3.2 整理，日期取 git 记录，**不要编造**。
- `package.json` 加 `"version": "3.2.0"`。
- README 加「自部署升级」一节：关注 GitHub Releases，拉取上游代码，看 CHANGELOG 里的不兼容变化，`npm run deploy`；Durable Object 的迁移由 wrangler 自动执行。

**编辑页的逻辑加固**（第二期，和 C 一起做）
- 成员重名检查：计算内核按名字区分人，重名会出错。
- 时区统一按北京时间显示日期。
- CDN 或计算环境加载失败时给出可重试的提示，不能整页报错。
- 本地存的「最近的行程」里，已删除的行程打开后提示并可以移除。
- 输入校验：车次格式、时间格式、日期、空座不小于 1、绕路不小于 0。
