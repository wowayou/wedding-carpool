# v3.10 计划：编辑页拆成模块，三种模式走同一个接口；端到端测试进仓库

分工：主代理出方案和验收，Sonnet 子代理执行。**这一版只做重构，界面和行为一点都不变**，所以不出预览页，改用改前改后的截图逐像素对比来证明。发布照常要等站长同意。

## 已定的决定（2026-10-09）

- 站长说「v3.10 开工」。范围按 [v3.8 计划](v3.8-plan.md) 第三节的路线：
  - 编辑页拆成同源的 ES 模块；
  - 三种模式（在线、本地、试玩）改成同一个接口的三个实现，模式分支集中到一处；
  - 把 Playwright 端到端检查放进仓库。
- **顺序**：先把端到端测试放进仓库、固定现有行为，再拆。
- 拆分只换文件，不改 [设计规范](design-system.md)「交互规范」里写的行为。规范里指向 `ui.html` 的地方，拆完改成指向模块。

## 一、现状（2026-10-09 实测）

- `ui.html` 共 2677 行：结构、样式和一段约 2360 行的内嵌脚本都在一个文件里；顶层函数约 171 个。
- **按模式分支**：
  - `mode === 'online'` 23 处、`mode === 'try'` 18 处、`mode === 'local'` 4 处；
  - `mode !== …` 7 处，`isTry` 9 处；
  - 另有 CSS 里 `body.try`、`body.online` 一类按模式显示和隐藏。
- **测试**：`web/ui.test.mjs` 用正则从页面脚本里抠出函数，放进沙箱跑。函数一改写法，测试就找不到它，3.6 时误报过一次。
- **浏览器检查**：Playwright 一直是从 npx 缓存（1.62.1）临时调用，脚本在 scratchpad 里，没有进仓库，也没有持续集成（仓库里没有 `.github/workflows`）。
- **相关的现成条件**：
  - CSP 的 `script-src` 已经放行 `'self'`，同源的模块文件可以直接加载；
  - 静态文件的缓存头是 `public, max-age=0, must-revalidate`（线上实测），部署后浏览器会重新验证，新旧文件不会长期混用，不需要在文件名里加版本号；
  - 本地版的静态文件由 `ui.py` 的 `STATIC_FILES` 提供。
- **在线模式**：可以在本地 `wrangler dev` 里完整走一遍：用站长口令登录管理页，生成邀请码，再用邀请码新建行程。数据都在本地，不碰线上。但 `.dev.vars` 里的 `AMAP_KEY` 是真的，所以端到端测试必须换成假的 Key，并且在线模式下不点「计算方案」，也不点「推荐车站」的「开始找」。

## 二、切片和验收

### A. 端到端测试进仓库（不改业务代码）

- **依赖**：`playwright` 作为开发依赖，版本固定为 1.62.1，和本机已下载的浏览器一致。不用 `@playwright/test`，沿用仓库现有的 `node:test`。
- **命令**：`npm run e2e`。它要起本地服务、开浏览器，所以**不放进 `npm test`**；README 写明什么时候跑，比如发布前、改编辑页以后。
- **测试代码自己起服务、自己收拾**：
  - 在线和试玩：起 `wrangler dev`，用随机空闲端口。用 e2e 专用的环境变量文件，`AMAP_KEY` 是假的、`ACCESS_CODE` 是测试口令；本地存储放到临时目录，不弄脏 `.wrangler/state`。
  - 本地：起 `ui.py`，配置文件是 `web/try-trip.json` 复制出的临时文件；Key 是假的，测试里不点会调用高德的按钮。
  - 测完按进程号停掉全部子进程，失败时也要停；不留临时文件。
- **场景**（每个都检查控制台没有报错）：
  - **试玩**：
    - 加载；改一个字段后方案显示「已过期」；
    - 校验清单弹窗，点一条能跳到那个输入框；
    - 计算方案，方案卡片和地图图层都出来；
    - 推荐车站：设置、估算、「开始找」不能点、地图上的找站过程；
    - 手机宽度的三个页签、深色模式、没有横向滚动；
    - 恢复示例。
  - **本地**：
    - 加载配置；改字段、保存，配置文件真的写进去了，第一次保存会生成 `.bak`；
    - 校验；
    - 推荐车站的设置面板（不估算，因为要查路线）。
  - **在线**：
    - 登录管理页、生成邀请码、用邀请码新建行程，打开 `/t/<行程>`；
    - 改字段、保存；第二个页面能实时收到改动；两边同时改同一格，出现冲突提示；
    - 历史版本抽屉；
    - 推荐车站的设置面板。
  - 任何场景下，只要页面发出了会调用高德的请求（在线模式的 `/api/amap`），测试就直接失败。
- **验收**：
  - `npm run e2e` 连续跑 3 次都通过，跑完没有残留的进程和临时文件；`npm test` 和 `npm run build` 照常通过；
  - 主代理在 scratchpad 存一套「改前」截图（桌面浅色和深色、手机，每种模式的主要状态），留给切片 B 对比。

### B. 编辑页拆成模块（重构，A 的端到端测试必须原样通过）

- **放在哪**：脚本拆到 `web/editor/*.js`；构建时复制到 `dist/editor/`，`ui.py` 也要能提供这些文件。`ui.html` 留下页面结构和样式，脚本改成 `<script type="module" src="/editor/main.js">`。Leaflet 和 marked 这两个全局脚本仍然先加载，构建时把地址换成 `/vendor/` 的做法不变。
- **按职责拆**，模块名由执行代理定，大致是：
  - 通用工具；配置项定义；
  - 行程状态（配置、未保存、保存）；
  - **后端接口和三种实现**；
  - 表单（画、绑定、校验）；三方合并和冲突；
  - 地图；推荐车站；方案和结果；
  - 弹窗、轻提示、进度条；历史和「更多」；
  - 启动入口。
  - 模块之间单向依赖，不要互相引用成环。
- **模式分支集中**：
  - 后端接口统一计算、找站、地点搜索、保存、发布方案页、历史这些操作；三种模式是这个接口的三个实现。
  - 「这个模式能不能做某件事」写成一个能力表（比如能不能保存、能不能实际搜索、有没有历史、能不能实时同步），在启动时按模式生成一次。
  - 其他模块只问能力表，不再判断 `mode`。
  - **加测试守住**：`mode ===`、`mode !==`、`isTry` 只出现在后端和启动这两个模块里。CSS 里按模式显示和隐藏的类保留。
- **模块加载失败时不能白屏**：留一小段内嵌脚本（按哈希放行），主模块几秒内没报到，就显示「页面没加载出来，刷新试试；你填的内容不会丢」一类的提示。
- **单元测试**：`web/ui.test.mjs` 改成直接 `import` 模块来测。模块在导入时不碰 DOM，只有启动入口碰。
  - 每个现有测试的断言意图都保留，测试数只增不减；
  - 正则抠函数的写法能去掉的都去掉。
- **CSP**：编辑页的大段内嵌脚本没了，只剩上面那段兜底脚本的哈希；构建检查照常通过。
- **验收**：
  - A 的端到端测试一个字都不改，原样通过，连续 3 次；
  - `npm test`、`npm run build` 通过；
  - 改前改后截图逐像素一致，有差异要逐张说明原因；
  - 汇报每个模块的行数和职责，以及 `mode` 判断还剩在哪里。

## 三、风险和边界

- **新旧文件混用**：静态文件每次都会重新验证，加载时拿到的都是新文件。页面已经打开的人，下次刷新才换成新版本，和现在一样。
- **本地版**：`ui.py` 要用正确的 MIME 提供 `.js`，否则浏览器拒绝加载模块。端到端测试里的本地场景会发现这个问题。
- **试玩页和编辑页**：`try.html` 是 `edit.html` 的副本，两者共用同一组模块。
- **不改的东西**：界面、文案、交互规范里写的行为，以及 Python 计算和 Worker 接口。

A 的做法：
- **不碰真 Key**：
  - `wrangler dev` 用临时的 `--env-file`，里面是假 Key 和测试口令，日志里一旦出现读了 `.dev.vars` 就失败；
  - 本地存储放在临时目录；
  - 本地版 `ui.py` 用假 Key，出站请求指向一个没人听的代理；
  - 浏览器里拦下所有发往高德代理或站外的请求，出现一次就算失败。
- **依赖**：新增开发依赖 `playwright` 1.62.1，版本固定。不下载浏览器，用本机 `~/.cache/ms-playwright` 里已有的。

A 发现的问题：
- **在线版冲突以后，状态栏可能停在「同步中…」**：已修（主代理，2026-10-09）。
  - 原因：自动保存的定时器触发时，如果改动已经存好，`syncSave` 直接返回，没有刷新状态栏。
  - 修法：返回前调用 `setStatus()`。
  - 测试：加了一个单元测试，去掉修复会失败；端到端的冲突场景里加了一条断言，合并重存后状态栏要自己回到「已同步」。
- **估算时车主路线查不到，不会报「估算没成功」**：这时跳过这位车主，照常给出估算，这是 v3.8 B 的设计（`summary.skipped_drivers`）。端到端测试接受两种结果，只要求页面不卡住。
- **在线版冲突时，控制台有一条 409**：这是正常流程，测试只对这一种放行。
