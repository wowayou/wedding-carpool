# v2 计划：多行程、并发与回退、通用的输入流程

目标：任何「多人从不同城市去同一个地方，有人开车、有人坐高铁」的活动都能用；多人同时编辑不丢改动、能回退；能提前确定的信息不重复请求。

已定的产品决定（2026-10-07）：

- 新建行程两种方式都支持：有**创建口令**的用站长的高德 Key（按行程和全站分别设每日上限，到上限就停下提示）；没有的**自带高德 Key**（Key 只存在服务端，不回传浏览器）。
- 车次：每人每站给出已填好出发地、到达站、日期的 **12306 查询链接**，查到后手填。不调 12306 的非公开接口。
- 返程规划这轮不做。

## 切片与验收标准

### 1. 后端：多行程

- `POST /api/trips` 新建行程，校验创建口令或自带 Key（用一次真实调用验证 Key 是否有效）；同一 IP 和全站每天的新建次数有上限。
- 每个行程对应一个 Durable Object 实例，保存配置、版本号、最近 100 个历史版本、当天调用量、方案页。
- 编辑权限即编辑链接：`/t/<id>#k=<编辑密钥>`。`#` 后面的部分不会发给服务器；页面用它换取一个只对该行程路径生效的 HttpOnly Cookie。
- 高德代理按行程鉴权和计数，按配额检查后再转发；配额用完的标记按 Key 分开记，自带 Key 的行程互不影响。
- 方案页每个行程一个固定链接 `/p/<id>`，重新发布会更新内容；旧的 `/p/<12位>` 链接继续可用。
- 验收：Worker 单元测试覆盖两种新建方式、鉴权、历史与恢复、方案页、各级上限。

### 2. 编辑器：并发与回退

- 进页面先留名字；顶部显示在线名单；别人正在编辑的格子标出名字。
- 保存时附带改动摘要；同一个人 2 分钟内连续的保存合并成一个历史版本。
- 历史面板：查看任一版本、一键恢复。恢复本身也是一个新版本，可以再撤回。
- 同一格冲突时显示提示：「你改成了 A，某某改成了 B」，并提供「改用对方的」。
- 验收：两个浏览器实测在线名单、编辑中标记、冲突提示、恢复历史。

### 3. 通用的输入流程：能提前确定的不重复请求

- 文案通用化：活动 / 目的地 / 成员。
- 表单顶部显示进度：目的地、成员、候选站、车次、计算。
- 地图实时显示已定位的目的地、成员和车站，不用等计算。
- 计算时按文字定位到的坐标写回配置，下次不再请求。
- 「推荐车站」：在目的地周边、各车主出发地附近、沿各车主路线找火车站；用 12306 站名表过滤掉不办客运的站，再按「到目的地车程」和「车主最少绕路」排序，勾选后加入。
- 12306 查询链接在本地拼出，不发请求。
- 配置可导入、导出；方案页加上分享摘要（微信转发时显示标题和描述）。
- 验收：Python 单元测试覆盖写回坐标和推荐车站；浏览器实测从空行程走到发布方案页的全过程。

### 4. 迁移与上线

- 把现在的「故城婚礼」配置迁移成一个用站长 Key 的行程，给出新的编辑链接；旧方案页链接继续可用。
- 部署到线上，在线上跑完整流程；更新 README。
