# v3.7 计划：去程和返程解耦，个人离场时间，拼车省钱，只规划返程

分工：主代理出方案和验收，Sonnet 子代理执行。

## 背景和已定的决定（2026-10-08）

站长问了三件事：去程和返程能不能自由组合；返程有没有必要规划；能不能尽量解耦、贴近实际。并要求把下面三项都做了：个人离场时间、拼车省钱优化、只规划返程。

- **自由组合**：现在已经可以。去程和返程是分开算的（`solve` 各算一次），界面上分别选，方案页按选中的「去程方案 i + 返程方案 j」生成。两段互不影响，比如同一个人去程坐老王的车、返程坐老张的车也行。这次要把这一点在界面和方案页上写清楚。
- **返程有没有必要**：散场时间晚、大家各自赶高铁的时候很有用，因为车主回家顺路就能把人送到站。但不是每个行程都需要，所以做成**和去程平级的可选项**。
- **解耦**：「规划哪几段」改成两个独立的开关，去程和返程各一个，至少开一个。只规划返程时，用不到去程的车次和出发时间。
- **规则版本升到 2**：拼车省钱改变了打车组的选站方式，会影响方案的总分钟和排序。按 `/guide/method` 写好的流程：T0 快照测试会失败，这次是**有意修改**，所以更新期望值，`RULES_VERSION` 改成 2，同时更新规则页和 CHANGELOG。**只有切片 C 可以改快照**，切片 A 和 B 必须让快照原样通过。

## 配置格式（只新增字段，旧配置照常能用）

| 字段 | 位置 | 默认 | 含义 |
|---|---|---|---|
| `outbound` | `[options]` | `true` | 规划去程。为 `false` 时只能规划返程，所以 `return.enabled` 必须为 `true` |
| `leave_time` | 每个成员 | 散场时间 `return.depart_time` | 这个人想几点离开目的地（返程） |
| `max_wait_min` | `[return]` | 30 | 返程时乘客最多愿意等车主多久 |
| `taxi_mode` | `[options]` | `"save"` | 打车怎么安排：`"save"` 尽量拼车省钱，`"fast"` 各人走自己最快的站 |
| `taxi_pool_extra_min` | `[options]` | 30 | 为了拼车，一个人最多比他自己最快的走法多花几分钟 |
| `taxi_wait_min` | `[options]` | 30 | 同一辆出租里的人，到站或离场的时间最多相差几分钟 |

默认值都进 `carpool.DEFAULTS`，规则页的默认值表要同步（测试会核对）。

## 切片

### A. 去程和返程解耦、只规划返程（不改规则，快照必须原样通过）

- **核心**：
  - `options.outbound = false` 时不算去程，`plans` 为空列表，只算返程。
  - 行车时间矩阵只查需要的方向：只有去程时和现在一样；只有返程时查「目的地 → 各点」和「各点 → 车主家」；两段都有时和现在一样。
- **校验**：去程和返程至少开一个。只规划返程时，要有返程的散场时间，还要有返程日期（填在 `return.date` 里，因为没有去程日期可以借用）。
- **报告**：只规划返程时，不出现「结论」「推荐方案」等去程的部分，直接从返程开始；「候选站对比」换成返程的口径，也就是从目的地出发、把人送到站时每位车主多绕多久，或者不显示。由执行代理决定，但不能出现去程的说法。
- **方案页**（`share.py`）：只规划返程时，只渲染返程那一节，地图画返程的路线。页面顶部写明选的是哪个组合，比如「去程方案 2 + 返程方案 1」，只有一段时就只写那一段。
- **界面**：
  - 表单顶部（目的地之前，或者「选项」里显眼的位置）加「规划哪几段：☑ 去程 ☑ 返程」，替代原来返程一节里的「也规划返程」开关；
  - 关掉去程时，隐藏成员卡片里去程的车次和分钟、出发日期和时间；
  - 步骤条和校验跟着变；
  - 方案区分开显示「去程方案」和「返程方案」两组卡片，现在就是这样，并加一句「去程和返程可以分别选，方案页按你选的组合生成」。
- **推荐车站**：只规划返程时也能用，沿车主「目的地 → 家」的路线去找。

### B. 个人离场时间（不改规则，快照必须原样通过：没填 `leave_time` 时结果完全不变）

- **语义**：
  - 每个人的 `leave_time` 默认等于散场时间；
  - **车主几点出发，车就几点走**；
  - 乘客能上这辆车，要满足：车主的离场时间晚于或等于这个乘客的离场时间，并且最多晚 `max_wait_min` 分钟。也就是乘客准备好以后，最多等车主 30 分钟；不会因为车主早走，就把乘客提前带走；
  - 原来「送到站要赶在发车前 N 分钟之前」的条件不变，时刻改为从车主的离场时间起算；
  - 打车的人，从他自己的离场时间出发；
  - 同行的一组人，用这组人登记的离场时间。
- **等待时间不计入总分钟**：只作为约束，规则页写明。
- **报告和方案页**：每辆车写自己的出发时刻；打车组写自己的出发时刻；乘客要等车的，写「等 N 分钟」。
- **界面**：返程开着时，成员卡片的返程部分加「离场时间」（可选，占位文字显示散场时间），返程一节加「乘客最多等（分钟）」。时间格式按现有的规则校验。

### C. 拼车省钱（改规则：`RULES_VERSION = 2`，有意更新快照）

- **打车组按时间切分**：
  - 现在去同一个站的人，不管时间差多远都算一组，这是个缺陷。
  - 改成：去程按到站后能上车的时刻（到站时间加出站时间），返程按离场时间，在 `taxi_wait_min` 以内的才拼一辆；超过 4 人按 4 人一辆拆开。
  - 没填车次、不知道时刻的人，当作可以和任何人拼，报告里写明「没填车次，按同一时间算」。
- **选站**：
  - **`taxi_mode = "fast"`**：每个人仍然走自己最快的站，只是按时间切分来分车、估打车费。这个模式的排序和现在一样。
  - **`taxi_mode = "save"`（默认）**：在没搭上顺风车的人里统一安排，目标依次是：
    1. **打车费最少**：车数 × 车程分钟数，打车费按每分钟约 1 公里粗估，和现有的估法一致；
    2. 其次总分钟最少；
    3. 约束：每个人选的站，「坐车到站 + 打车」的用时不超过他自己最快走法加 `taxi_pool_extra_min`；返程还要赶得上车次。
- **计算量**：
  - 打车安排只取决于「哪些人没搭上车」，所以按这个人群做缓存，同一组人只算一次；
  - 组合数在 20,000 以内时穷举；超过时用贪心法：先各走最快的站，再把人挪到已经有人去的站，只要不超过多花上限、能省钱就挪。规则页写明这个近似。
- **排序**：总分钟里的「打车组」改按新的选站来算，排序规则本身不变（搭车人数 → 总分钟 → 停车次数）。打车费只用来选站，**不参与方案之间的排序**。
- **展示**：
  - 每个方案的「排序依据」之后加一行「打车：N 辆，粗估 X–Y 元」，没人打车就不显示；
  - 界面的方案卡片加「打车 N 辆」；
  - 方案页的打车组卡片写明和谁拼一辆、在哪汇合、几点。
- **规则页 `/guide/method` 改成第 2 版**：
  - 写明拼车省钱的目标、约束和近似；
  - 写明时间切分和个人离场时间；
  - 「目前没考虑的」更新：等人的时间现在有上限，但不计入总分钟；拼车已经按省钱安排；车主之间负担均衡仍然没考虑。
  - 加一节「规则变更记录」：第 1 版到第 2 版，改了什么，为什么改。

- **切片 A、B 提交后，T0 规则快照原样通过**。切片 C 是唯一改快照的提交：提交信息写明原因，`RULES_VERSION` 改成 2，规则页显示「第 2 版」，`MethodPageTest` 通过。

  - 拼车省钱：两个人的最快站不同，但有一个共同的站、都在多花上限以内时，省钱模式会让他们拼一辆，省时间模式不拼；超过多花上限的不拼；时间差超过 `taxi_wait_min` 的拆成两辆；超过 4 人拆车；组合数超限时走贪心，结果仍然可行；

  - 界面静态检查：两段的开关、离场时间输入框、打车方式选项都在；
  - 试玩模式能切换只规划返程。
- **浏览器验收**：在本地 `wrangler dev` 的 `/try` 上走一遍，**不调用高德**：
  - 两段都开：先算一次，再把某位乘客的离场时间改得很早，再算；
  - 只规划返程：再算一次；
  - 把打车方式切成「省时间」再算；
  - 看报告和方案卡片的变化，确认没有脚本错误、手机宽度没有横向滚动。
- **在线编辑页不能退化**：在管理页新建一个行程，确认能加载、能改设置并自动保存。**不点计算**，在线行程一计算就会调用高德。
