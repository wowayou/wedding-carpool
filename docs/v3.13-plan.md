## 一、问题

v3.12 把「每个人的用时」摆了出来，也写明了缺口：

- 车主绕路有上限（每人自己设），拼车打车的人有上限（`taxi_pool_extra_min`，默认 30 分钟）。
- **搭顺风车的乘客没有上限**。排序先比搭车人数，所以只要能多带一个人，程序会让某位乘客坐更慢的车去一个远站等车主，或者坐一辆绕了很多路的车，哪怕比他自己打车慢一两个小时。

## 二、规则

新增配置 `options.ride_extra_min`，中文名「搭车最多多花」，默认 30 分钟，最小 0，列进规则页默认值表。

**硬性条件**：一位乘客能在某辆车的某个点上车（返程是下车），要满足

> 「不算等人」的全程 ≤ 自己单独走 + `ride_extra_min`

不满足的上车点在分配时直接不考虑，和「返程赶车次」一样是硬性条件，不是加分减分。

**口径和 v3.12 的「每个人的用时」表一致**：表里的「全程 − 其中等人」就是这里的「不算等人的全程」，「自己单独走」就是表里的同一个数（`timetable.solo_minutes`）。所以报告里任何一位搭车的人都满足「比自己单独走多花的 − 其中等人 ≤ 上限」。等人的时间不算进去：去程等同车的人和车主，取决于别人的车次；返程等车主已经有「乘客最多等车主」管着。

按场景写出来（`seq` 是这辆车的点序列，`opts` 是 `rider_options` 给的到上车点的分钟数，`margin` 是返程发车前提前量）：

| | 不算等人的全程 | 自己单独走 |
|---|---|---|
| 去程，在站上车 | `opts[站]` + 出站时间 + 上车点到目的地的车程（沿这辆车剩下的点） | 各候选站里最快的：`opts[站]` + 出站时间 + 站到目的地的车程 |
| 去程，在家附近上车 | 上车点到目的地的车程（沿这辆车剩下的点） | 同上 |
| 返程，送到站，填了这个站的回程车次 | 发车时刻 − 车主的离场时间 + 回程用时 | 各赶得上的站里最快的：发车时刻 − 自己的离场时间 + 回程用时 |
| 返程，送到站，没填车次 | 目的地到下车点的车程（沿这辆车前面的点）+ `margin` + 回程用时 | 各站里最快的：站的车程 + `margin` + 回程用时 |
| 返程，送到家附近 | 目的地到下车点的车程（沿这辆车前面的点） | 同上两行 |

**没有可比的不拦**：一个能自己打车去的站都没有的人（`solo_minutes` 是 None），不受这个上限，否则他只能「待安排」。

**想要第 2 版的结果**：把 `ride_extra_min` 设得很大（比如 999）。

## 三、实现要点

- 判断放在 `solver.evaluate` 给 `assign` 的 `allowed` 里，和返程赶车次的判断合在一起：一个上车点要两条都满足。去程现在 `allowed` 是 None，加上限后去程也要传。
- 「自己单独走」每次求解按人算一次；「上车点到目的地的车程」按路线缓存（`Route` 是不可变的，可以做字典键），不要在 3 万个组合里重复算。
- 「不算等人的全程」写成一个函数，`timetable` 里的 `person_times` 和求解共用同一个口径的代码或至少由测试核对两边一致，不能各写一套慢慢走样。注意模块依赖方向：`timetable` 已经引用 `routes`，`solver` 可以引用 `timetable`，反过来不行。
- 打车的安排（`TaxiPool`）不动；被上限挡下的人走原来的打车逻辑。
- `RULES_VERSION` 改成 3。

## 四、对已有行程的影响（CHANGELOG 要写明，标「计算规则升级」）

- 有人搭车、并且某位乘客搭车比自己单独打车多花 30 分钟以上（不算等人）的方案，会少带这个人，他改为打车；搭车人数、选站、总分钟可能和以前不一样。
- 其他行程结果不变。方案之间的排序规则没变，仍是搭车人数、总分钟、停车次数。
- 想保持第 2 版：`ride_extra_min = 999`。
- 自部署：不算不兼容，新配置可以不写。

## 八、验收时发现的问题（2026-10-13，主代理）

**现象**：金标准 `two_cars` 的返程里，小李被送到西站「比自己单独走多 2 小时 21 分」，新上限因此不让老王送他去西站；新的返程方案 3 里打车的小周也「多 2 小时 14 分」。可是两人的回程车次都只在一个站（小李 `G2 西站22:30→a`，小周 `G4 近站22:30→b`），按规则页「硬性条件」里「填了某些站的车次或分钟数的人，只会去这些站（返程看回程车次）」，他们本来就只能去这一个站，不该和别的站比。

**根因**（v2 起就有，3.12 的用时表把它显出来，第 3 版的上限把它放大）：
- `routes.rider_options` 只看分钟数（`rail_min` / `back_rail_min`）来决定「只去这些站」。
- 分钟数由车次推算，要有首尾两个时刻（`model.load_places` 里 `len(times) >= 2`）。
- 回程车次只写了发车时刻（返程最在意的就是发车时刻，这样填很常见），分钟数推不出来，「只去这些站」就失效了：
  - 这个人可能被安排去一个他没有车次的站（打车或搭车）；
  - 「自己单独走」也拿没有车次、不用等车的站来比，算出虚高的「多花」。

**修正**（算进第 3 版，规则页的写法本来就是这样，代码改成和它一致）：
- `rider_options` 里「这个人填了的站」是这一段的分钟数和车次两者的站名合集（按候选站过滤）。
- 合集不为空，就只去这些站：
  - 每个站的分钟数，有就用；
  - 没有的，去程用高德估算（`rail_est`），再没有就用 `station_cost`；返程用 `station_cost`。
- 合集为空，和现在一样。
- 别处如果也用 `p.rail_min` / `p.back_rail_min` 是否为空来判断「填没填」（比如估算公共交通时跳过谁、报告里的说明），一起核对，口径要一致。

**验收**：
- 新用例：
  - 返程只填了发车时刻的人，打车和搭车都只去这个站，「自己单独走」也按这个站的车次算；
  - 去程同理（车次只有一个时刻时）；
  - 都要在修正前失败。
- `two_cars` 金标准重新生成：小李、小周的「比自己单独走」不再出现这种虚高，逐项说明变化。
- 其他金标准和规则快照如有变化，逐个说明原因。
- 规则页「规则变更记录」第 3 版和 CHANGELOG 加一句：只填了发车时刻的车次，也算填了这个站。
- `npm test`、`npm run e2e` 全过。
