# wedding-carpool

一群人从不同城市去参加婚礼：有人开车，有人坐高铁。这个工具用高德的真实行车时间回答三个问题：

- 不开车的人坐到哪个高铁站最合适（不一定是离场地最近的那个）；
- 哪位车主顺路接谁、在哪接、几点出发，绕路不超过各自的上限；
- 搭不上车的人在哪个站汇合打车。

结果包括：

- 推荐方案和备选方案；
- 候选站对比表；
- 每辆车的路线地图：灰色虚线是不接人时的直达路线，和实际路线对比就能看出绕了哪段；
- 一页可以直接发给大家的**方案页**：每人一张时间线卡片，带高德导航链接。

有两种用法：**本地版**（`python3 ui.py`）和**在线版**（Cloudflare Workers，带口令）。两者的计算代码是同一份 Python。

## 准备高德 Key

1. 登录 [高德开放平台控制台](https://console.amap.com/)（个人开发者需要实名认证）。
2. 「应用管理 → 我的应用 → 创建新应用」，再「添加 Key」，服务平台选 **Web服务**。

一次计算大约调用二三十次接口，在个人免费额度内。**配额用完时程序会停下提示，不会继续调用**；要不要购买额度由你自己决定。

## 本地版

需要 Python 3.11+，只用标准库。Key 放在环境变量 `AMAP_KEY` 里，或者存进同目录的 `.amap_key`（已加入 `.gitignore`）。

```bash
python3 ui.py            # 编辑 trip.toml；没有这个文件时从示例开始
# 浏览器打开 http://127.0.0.1:8765
```

- 左边填场地、候选站和每个人的信息。地点旁的「搜索」会列出高德的候选点，点一个就填好坐标；车站行只搜火车站。
- 不开车的人在每个站后面填 12306 查到的车次和时刻（如 `G1234 08:00→11:30`）。程序按「第一个发车 → 最后到站」再加「去车站+候车」（默认 45 分钟）算出用时，并按到站时间倒推车主几点出发。也可以只填分钟数。都留空表示不去这个站。
- 「计算方案」会先保存再计算。右边地图画出每辆车的高德实际路线，可以在三个方案之间切换，下面是完整报告。
- 「生成方案页」把当前方案写成 `trip-plan.html`。页面不含不开车的人的家庭位置。
- 保存时会把配置写回 TOML，手写注释不会保留：第一次保存前，原文件备份为 `trip.toml.bak`。要留的说明请写在「备注」里。
- 服务只监听本机，Key 不会发到浏览器。

也可以只用命令行：

```bash
cp trip.example.toml trip.toml   # 改成你们的信息，字段说明见文件里的注释
python3 carpool.py trip.toml     # 报告打印到终端，并写到 trip-report.md
```

## 在线版（Cloudflare Workers）

```
浏览器：界面 + Pyodide（浏览器里运行的 Python，跑 carpool.py 等）
   │  口令登录后带 Cookie
   ▼
Worker（web/worker.js）：口令校验 / 高德接口代理（加 Key、只放行用到的接口）/ KV 存配置和方案页
```

- 计算在浏览器里进行，Worker 只做转发和存储，免费套餐够用。第一次计算要下载约 12MB 的 Pyodide。
- 编辑和计算需要口令。方案页发布在 `/p/<随机 id>`，拿到链接的人不用口令就能看，半年后过期。
- 高德返回配额用完时，Worker 会记下来，到北京时间次日零点前不再转发。

部署步骤（需要 Node.js 和 Cloudflare 账号）：

```bash
npm install
npx wrangler login
npx wrangler kv namespace create DATA      # 把输出的 id 填进 wrangler.jsonc
npx wrangler secret put AMAP_KEY           # 高德 Web 服务 Key
npx wrangler secret put ACCESS_CODE        # 登录口令
npm run deploy                             # 构建 dist/ 并部署
```

要用自己的域名，在 `wrangler.jsonc` 里加 `"routes": [{ "pattern": "子域名.你的域名", "custom_domain": true }]`，域名需要已经托管在 Cloudflare。`workers.dev` 域名在国内不翻墙常常打不开。

本地调试：在 `.dev.vars` 里写 `AMAP_KEY=...` 和 `ACCESS_CODE=...`，然后运行 `npm run dev`。

## 方案怎么排序

1. 先让尽量多的不开车的人搭上顺风车，每位车主的绕路不超过他的 `max_detour_min`。
2. 再比总分钟数：车主绕路时间 + 乘客坐车到接驳站的时间 + 打车组从车站到场地的车程。
3. 乘客到各站的用时，优先用车次或手填的分钟数，其次用高德公共交通估算，都没有时按 `station_cost_min` 估算。

## 已知限制

- 行车时间来自高德驾车测距，接近查询时的路况，每次查都会浮动几分钟，当天也可能有出入。
- 高德的跨城公交规划只给直达火车，不含火车换乘，也查不到刚开通的线路（实测给出过十几个小时的普速车方案）。车次请在 12306 查好填进去。
- 填了车次时刻才能倒推车主出发时间。到站后默认留 15 分钟出站，可在选项里改。
- 遇到网络中断或接口频率限制会自动重试 3 次；配额类错误不重试，直接停下提示。
- 自动搜站用的是高德的「火车站」分类，会混进普速站和货运小站，也可能漏掉附近的高铁大站。只能当线索，候选站最好人工列出来。
- 车站按名称搜索，搜不到会直接报错（加上城市再试），不会退回按地址解析，那样容易定位到同名的其他地方。
- 报告里有每个人出发地的坐标，只发给相关的人。
